# Журналювання й реакція на аномалії

Модуль `logger_setup.py` створює `.aes-lab/logs/aes.jsonl` (POSIX 0600). Кожна подія записує час UTC, назву дії (`enc`, `dec`, `key.new`, `key.rotate`), статус (`success` або `failed`), режим, розмір даних, час та класифікацію помилки. **Паролі, ключі, вхідний текст і повні шляхи не записуються.**

Приклад анонімізованої структури події:

```json
{"time_utc":"2026-11-26T13:00:00+00:00","event":"dec","status":"failed","mode":"gcm","size_bytes":0,"duration_ms":0.5,"error_type":"IntegrityError"}
```

Вище наведено **ілюстрацію структури**, а не реальну подію з указаним часом. Реальна демонстрація описана в [verification.md](verification.md).

Огляд:

```bash
python aes_cli.py logs summary
# Або відфільтрувати помилки (без викладення персональних даних):
grep '"status": "failed"' .aes-lab/logs/aes.jsonl
```

Рекомендації: серія `dec:failed` і `IntegrityError` може вказувати на випадкове пошкодження, невідповідне AAD або навмисну підміну; не вважати кожну таку подію атакою без додаткового контексту. Багато `InvalidPassword` — сигнал спроб перебору. Для реального застосунку потрібні централізовані збережені журнали, захист від зміни, контроль доступу, нормативний строк зберігання та сповіщення.
