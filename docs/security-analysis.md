# Аналіз захисту, винятків і обмежень

## Властивості режимів

| Режим | Конфіденційність | Цілісність/автентичність | Параметри | Особливості |
|---|---|---|---|---|
| AES-GCM | Так | 128-бітний GCM tag, автентифікований заголовок + AAD | nonce 96 біт, padding відсутній | Переважний режим; повторення nonce з тим самим ключем критично небезпечне |
| AES-CBC + HMAC | Так | HMAC-SHA256 Encrypt-then-MAC (32 байти) | IV 128 біт, PKCS#7 або вирівняне none | MAC перевіряється **до** CBC дешифрування, щоб уникнути padding oracle |
| AES-CTR + HMAC | Так | HMAC-SHA256 Encrypt-then-MAC | IV/counter 128 біт; padding відсутній | Без MAC CTR має malleability, тому MAC тут обов'язковий |

Для AES `block_bits=128` — алгоритмічний інваріант; 128/192/256 стосуються **довжини ключа**, не блоку. IV/nonce створюється випадково, пряме ручне встановлення у звичайному інтерфейсі заборонене.

## Модель порушника

- Локальний користувач або сторонній процес може прочитати та змінити зашифрований файл, але **не знає** парольної фрази.
- Порушник може змінити тег, IV, шифртекст, JSON-заголовок або обрізати файл.
- Порушник може копіювати старі цілі файли й повертати їх (replay); базова автентифікація **не запобігає** replay — потрібні зовнішні версії, журнал транзакцій або anti-rollback сховище.

## Негативні ситуації та реакція

| Умова | Реакція | Файл відкритого тексту |
|---|---|---|
| Хибний пароль | `InvalidPassword` | Не створюється |
| Невідомий key-id | `KeyManagementError` | Не створюється |
| Невірний magic/header | `ContainerError` | Не створюється |
| Підміна GCM-тегу | `IntegrityError` | Не створюється |
| Підміна CBC/CTR HMAC або шифртексту | `IntegrityError` | Не створюється |
| Підміна зовнішнього AAD | `IntegrityError` | Не створюється |
| Помилкова довжина ключа | `ContainerError` | Не створюється |
| CBC без padding із некратним 16 розміром | `ContainerError` до шифрування | Не створюється |
| Існує вихідний файл | `FileExistsError` без `--force` | Не змінюється |
| Ліміт використань чи віку ключа | `KeyManagementError` при encryption | Не створюється |

**Важливо:** у режимі GCM модуль може тимчасово створити захищений файлик з проміжними байтами *до* фінальної перевірки тегу. Цей тимчасовий файл має POSIX-права `0600` і видаляється при помилці; користувацький кінцевий файл з'являється **тільки після успішної автентифікації**. Для високочутливих даних рекомендовано захищений диск/тимчасову файлову систему.

## Обмеження

- Немає незалежного криптографічного аудиту. Реалізація використовує стандартну бібліотеку `cryptography`, а не власноруч створений AES.
- Сховище метаданих/парольний verifier потенційно дозволяє офлайн-перебір слабких паролів; мінімальна довжина — лише перевірка UX, не гарантія ентропії.
- `MAX_ENCRYPTIONS=100` не гарантує відсутності nonce-колізій у розподіленому середовищі; кілька екземплярів із копіями сховища не мають глобального атомарного лічильника.
- Немає гарантії стирання ключового матеріалу з пам'яті Python. Немає обмеження на replay, криптографічне резервування, політики KMS/HSM чи безпечну міграцію пароля з автоматичним re-encrypt.
- Потоковий API не означає, що вбудовані засоби повністю захищають від DoS дуже великими/некоректними файлами; потрібне обмеження обсягу і квот.

## Рекомендації

Перейти на KMS/HSM та сильні паролі/ключі; реалізувати міграцію за зміни пароля; обмежити максимальний розмір файлів; додати lock-файл/атомарний лічильник при одночасному доступі; запровадити політики backup/retention; за потреби додати authenticated anti-replay механізм; проводити регулярний огляд залежностей.
